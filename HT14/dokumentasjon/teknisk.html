    1 Kort for alle

    Hva er det?

    Badehusappen er en nettside som oppfører seg som en app. Der ser vi når badehuset er ledig, booker, avbestiller og sjekker inn. Den virker på mobil, nettbrett og PC, og du kan legge den på Hjem-skjermen – ingenting å laste ned.

    I dag sender vi en e-post til en nabo som har oversikten. Det har fungert fint takket være ham, men det blir mye e-post, og alt hviler på én person. Med Badehusappen ser alle den samme kalenderen og booker selv.

    Dagen er delt i tre perioder: formiddag 10–14, ettermiddag 14–17 og kveld 17–24. Reglene for hvem som kan booke hva står i Regler for bruk av badehuset.

    Hvem kan gjøre hva

    Alle brukere hører til ett hus (A, B, C eller D) og kan se kalenderen, booke, avbestille, sjekke inn, bekrefte bruk og se all historikk og statistikk. To administratorer kan i tillegg opprette og deaktivere brukere, tilbakestille passord, logge ut en mistet mobil, legge inn regelendringer, gjøre unntak og rette feil. Alt administratorene gjør, logges.

    Trygghet og personvern

    • Ingen registrerer seg selv – en administrator lager brukeren. Du logger inn med e-post og passord, mobilen kan huske passordet, og du holder deg innlogget i omtrent ett år.
    • Bookinger er personopplysninger. De ligger i et privat lager, aldri på de offentlige sidene. Passord lagres aldri i klartekst.
    • Ingen bookinger slettes, og alle endringer kan spores. Flytter noen, deaktiveres brukeren og navnet kan byttes til «Tidligere beboer Hus A».
    • Ikke med i starten: varsler på e-post/SMS og innlogging med Face ID uten passord (passkeys). Det kan komme senere.

    2 Overordnet (HLD)

    Hvilke deler løsningen består av, og hvorfor. Arkitekturen er Thomas sitt tekniske valg; kontoene eies av ham via FluxReveal, og dataene tilhører sameiet.

    Komponenter

    Ønsket fra start var ingen database, ingen server og ingen kostnad. Men GitHub Pages alene kan ikke gi sikker innlogging eller skriving: en nøkkel i JavaScript kan alle lese, og alt på Pages er offentlig. Derfor:

    DelHva den gjør
    Badehusappen (HTML, CSS, JS)Kalender, booking, innsjekk, historikk, statistikk og admin. Blir servert av Workeren på badehusappen.fluxreveal.workers.dev. Kan legges på Hjem-skjermen.
    Cloudflare Worker (gratis)Innlogging, økter og all skriving. Sjekker alle regler på nytt mot rules.json og lagrer i data-repoet.
    Workers KV (gratis)Liste over innloggede mobiler og teller for feil passord.
    Privat data-repo på GitHubBrukere, bookinger, logg og regler som JSON. Git-historikken er revisjonssporet.
    GitHub Actions (nattlig)Skriver endelig status, lager CSV-arkiv og backup.
    GitHub PagesStartsiden og denne dokumentasjonen på fluxreveal.com/HT14/. Ingen data, ingen innlogging.

    Alt kjører på gratisplanene, så det koster 0 kr. Fire hus som booker badehuset, kommer aldri i nærheten av grensene.

    Dataflyt

    Status («pågår», «ferdig») regnes ut fra klokka i norsk tid når noe vises, så det blir riktig selv om nattjobben er forsinket. Hver periode lagres som en egen booking; en heldag er tre bookinger med felles groupId.

    Innlogging og økter

    Badehusappen har egen innlogging med e-post og passord, sjekket i Workeren. Passordene lagres bare som PBKDF2-hash. Skjemaet bruker riktige autocomplete-verdier, så iPhone og Android tilbyr å lagre passordet og fyller det inn med Face ID eller fingeravtrykk.

    Etter innlogging får mobilen en sikker cookie (HttpOnly, Secure, SameSite=Lax) som varer i ca. 365 dager og fornyes ved bruk. Sidene og API-et ligger på samme adresse, så cookien er en vanlig førsteparts-cookie som også Safari på iPhone godtar. En administrator kan logge ut én mobil eller alle økter for en bruker, og etter flere feil passord blir det en kort pause.

    Sikkerhet

    • Data: ligger i et privat repo, og bare Workeren har nøkkelen (et GitHub-token som når kun data-repoet, lagret som Worker-secret – aldri i kode).
    • Regler: sjekkes alltid i Workeren, så det hjelper ikke å fikle med JavaScript i nettleseren.
    • Andre nettsider: Workeren godtar bare endringer fra sin egen adresse (Origin-sjekk), sender ingen CORS-headere og krever gyldig økt.
    • Dobbeltbooking: hindres med optimistisk låsing – GitHub avviser en skriving hvis fila er endret siden den ble lest, og Workeren sjekker på nytt.
    • Sporbarhet: hver endring er en commit og en linje i loggen med hvem, når, fra, til og kommentar.

    Tekniske valg

    Thomas har vurdert flere løsninger. Bare GitHub Pages ble valgt bort fordi passord og nøkler i JavaScript ikke kan holdes hemmelige. Egen GitHub-konto for hver nabo ble for tungvint. Sidene på fluxreveal.com med bare API-et hos Cloudflare ville gjort cookien til en tredjeparts-cookie, som Safari blokkerer – og domenet skal ikke flyttes. Cloudflare Access gir maks 30 dagers innlogging med engangskoder på e-post, som mobilen ikke kan huske.

    Avhengigheten er gratisplanene til GitHub og Cloudflare. Endrer de seg, kan Workeren flyttes med små endringer – dataene ligger i Git.

Gamle prøvedata gjøres om automatisk når reglene endres.

    Regelmotor

    rules-engine.js er rene funksjoner uten sideeffekter, så samme kode kjører i nettleseren (rask tilbakemelding) og i Workeren (som bestemmer). Input er forespørselen, eksisterende bookinger, rules.json og «nå» i norsk tid.

    • validateBooking sjekker én periode i denne rekkefølgen: gyldig input → ikke passert → ikke startet → innenfor 3 måneder → ledig → (admin-unntak) → under 7 dager? da OK → sommer og fre/lør/søn? → kvote per ukedag → én dag per helg.
    • validateBookingMulti tar flere perioder: heldag avvises etter kl. 10, og hver periode sjekkes mot de andre i samme forespørsel. Alt eller ingenting.
    • Kvoten teller dager, ikke perioder. Hver periode avbestilles for seg; tidlig eller sen avbestilling avgjøres av antall dager igjen.
    • tests/rules-engine.test.js dekker eksemplene i reglene og kjøres med node --test tests/.

    Statuser

    CANCELLED og CANCELLED_LATE frigjør perioden. CANCELLED_LATE teller fortsatt i sommerkvoten. I statistikken teller CHECKED_IN og COMPLETED som bruk, NOT_CONFIRMED vises for seg.

    API

    Alle kall går til /api/ på samme adresse, med JSON og økt-cookie (unntatt innlogging).

    EndepunktHva
    POST /api/login, /logout, /password, GET /api/meInnlogging, utlogging, bytte passord, hvem er jeg
    GET /api/calendar, /history, /stats, /rulesKalender (uke/måned), historikk, statistikk, regler
    POST /api/bookings {date, periods}Book én eller flere perioder
    POST /api/bookings/{id}/cancel | checkin | confirmAvbestill, sjekk inn, «Vi brukte badehuset»
    POST /api/checkin {periods}Spontan innsjekk uten booking
    /api/admin/…Brukere, økter, regler, unntak, retting, import og eksport

    Feilkoder

    Feil returneres som { "error": KODE, "message": tekst }, og brukeren ser alltid en forståelig norsk melding. De vanligste: SLOT_TAKEN (perioden er tatt), STARTED (har startet – bruk «Sjekk inn nå»), FULLDAY_STARTED (heldag etter kl. 10), OUTSIDE_WINDOW (over 3 måneder), QUOTA_WEEKDAY og WEEKEND_LIMIT (sommerreglene), RATE_LIMITED (for mange feil passord), RULES_INVALID (feil i rules.json) og CONFLICT_RETRY (mange skrev samtidig).

    4 Drift og oppsett

    For administratorene. Ingenting her krever at du er utvikler.

    Oppsett fra start

    Slik går utkastet over til ekte innlogging og felles data. Alt med kontoer, passord og tokens gjør Thomas selv. Domenet fluxreveal.com røres ikke.

    1. Cloudflare-kontoRegistrer med FluxReveal-e-posten, bekreft e-posten, slå på totrinnsinnlogging og lagre reservekodene. Velg workers.dev-navn (forslag: fluxreveal) før naboene får adressen.
    2. Privat data-repoLag FluxReveal/badehus-data (Private) med users.json, rules.json, bookings/<år>.json og en tom audit/<år>.jsonl.
    3. GitHub-tokenFine-grained token med tilgang bare til badehus-data (Contents: read and write), utløp om ca. ett år. Legg inn en kalenderpåminnelse om fornying.
    4. KV-lagernpx wrangler kv namespace create OKTER, og lim id-en inn i wrangler.toml.
    5. Worker og hemmeligheternpx wrangler deploy, deretter npx wrangler secret put GH_DATA_TOKEN og SESSION_PEPPER. Hemmeligheter legges bare inn som Worker-secrets – aldri i koden.
    6. Lenke fra startsidenKnappen «Badehusappen» på fluxreveal.com/HT14/ peker til den nye adressen.
    7. Første administratorerFørste admin legges inn for hånd i users.json med midlertidig passord; nestleder opprettes fra adminsiden. Test på iPhone og Android: logg inn, lagre passord, Hjem-skjerm, book og avbestill.
    8. NattjobbLegg inn nightly.yml i data-repoet og kjør den manuelt én gang (Actions → Run workflow).

    Brukere

    • Ny bruker: Adminsiden → Brukere → «Ny bruker»: navn, e-post, hus og rolle. Gi startpassordet muntlig eller på lapp. Første gang velger beboeren sitt eget passord.
    • Flytter noen: «Deaktiver» med kommentar. Brukeren logges ut overalt, historikken beholdes.
    • Glemt passord: «Tilbakestill passord». Alle økter avsluttes og pausen etter feil forsøk nullstilles.
    • Mistet mobil: Brukere → «Innlogginger» → «Logg ut» på den mobilen (eller «Logg ut alle»).

    Endre regler og gjøre unntak

    Når sameiet har bestemt en endring, legger administratoren den inn i rules.json – helst via adminsiden, som sjekker at fila er gyldig. Retter du direkte på github.com, pass på komma og anførselstegn: en feil gjør at alle bookinger avvises med RULES_INVALID, og da går du tilbake til forrige versjon. Unntak fra reglene og retting av historikk krever alltid en kommentar og vises i historikken.

    Backup og eksport

    Data-repoet er backupen: hver endring er en commit, og alle tidligere versjoner kan hentes fram (fila → History). Nattjobben lager i tillegg archive/<år>.csv (semikolon, UTF-8, åpnes i Excel). Last gjerne ned en eksport etter hver sommer og legg den i sameiets arkiv.

    Når noe feiler

    SymptomHva du gjør
    En beboer kommer ikke innSjekk at brukeren er aktiv og e-posten riktig. Vent noen minutter, eller tilbakestill passordet.
    «Tjenesten er midlertidig utilgjengelig»Sjekk status hos GitHub og Cloudflare, og at tokenet ikke er utløpt.
    Alle bookinger avvises (RULES_INVALID)Gå tilbake til forrige versjon av rules.json.
    CSV oppdateres ikkeSe Actions i data-repoet og kjør jobben manuelt. Brukerne ser likevel riktig status.
    Feil i en bookingRett den med kommentar.

    Overlevering

    Det skal alltid være to administratorer. Ved bytte: gi admin-rolle i Badehusappen og tilgang i GitHub og Cloudflare, lag nytt token, fjern tilganger for den som går av, og test en booking. Skal sameiet en gang eie alt selv, kan data-repoet overføres, mappen HT14/ kopieres til sameiets eget repo og Workeren settes opp på sameiets Cloudflare-konto med nye hemmeligheter. Da får Badehusappen ny adresse, og alle logger inn én gang til.
